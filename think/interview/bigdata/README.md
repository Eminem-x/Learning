# 大数据面试复习资料

> 面向「维护过 ETL、对主流大数据组件有了解、准备面试」的复习包。
> 每篇都按 **概念 → 为什么解决这个问题 → 例子 → 面试高频问答** 组织，
> 多篇引用了真实生产项目里的踩坑案例（可当作面试的「实战经验」讲）。

## 一张图先建立地图

一条数据从产生到被消费，流经四层。下面每篇文档正好对应地图的一环：

```
                         ┌──────────────── 调度层：Airflow（谁先跑、定时、重试）──────────────┐
                         │                          [06]                                      │
  业务系统 ──► S3 原始文件 ──► Hive 建表 ──► Spark 清洗聚合 ──► StarRocks / ClickHouse / ES ──► 产品/BI
              [02 存储层]      [02]          [01 计算·批]         [04 OLAP 服务层]
                                   ▲              │
                    Trino [03] ────┘（随时对着湖做交互式 ad-hoc 查询）
                    数仓建模 [05] 贯穿始终：fact/dim、分层、粒度决定这些表长什么样
                    核心术语 [00] 是看懂以上一切的底座
```

**四层心智模型**：存储层（放住）→ 计算层（算一遍）→ 服务层/OLAP（查得快）→ 调度层（按时按依赖跑）。
维度建模是正交的一维（表怎么组织），术语是通用底座。

## 推荐复习顺序

按「先底座 → 后你的主战场 → 再周边」的顺序，而不是编号顺序：

1. **`00` 核心概念** —— 先把术语底座打通，后面所有文档的黑话都在这里解释过。
2. **`01` Spark** —— 你的日常，也是面试最重的加分项，值得花最多时间。里面的真实事故案例建议能复述出来。
3. **`05` 数仓建模** —— 把「dim」从一个词升级成一套体系，回答"你们数仓怎么分层/建模"这类必考题。
4. **`02` 存储层 + `03` Trino** —— 补齐 Spark 上下游（数据从哪读、算完谁来查）。
5. **`04` OLAP 服务层** —— 记住那个选型口诀就能答好"ES/CH/SR 怎么选"。
6. **`06` Airflow + MongoDB** —— 调度是 ETL 岗的基本盘，`execution_date` 和幂等是高频考点。

## 面试临场速记（一句话版）

- **Shuffle** = 按 key 跨节点重排，最贵的操作，慢和挂多半赖它。
- **Broadcast join** = 小表复制到每个节点，用空间换 shuffle。
- **Partition 两义** = Hive 表分区（存储/分区裁剪）≠ Spark 分区（并行度）。
- **Lazy** = 不到 action 不算；一个 job 多个 action 会把上游重算 N 次。
- **数据倾斜** = 某 key 数据超多，一个节点扛 90% 的活拖死全局。
- **列存为什么快** = 只读要的列 + 同列同类型高压缩 + 向量化。
- **Trino vs Spark** = 交互式全内存查询 vs 可落盘容错的重型批处理。
- **ES/CH/SR 选型** = 要搜→ES；单表狂算日志埋点→ClickHouse；多表实时数仓对外服务→StarRocks。
- **fact vs dim** = 事实表记"发生了什么"(量大)，维表记"是什么"(量小)。
- **数仓为什么分层** = 复用、解耦、口径统一（ODS→DWD→DWS→ADS）。
- **execution_date** = 数据的逻辑日期，不是实际运行时刻；T+1 里它是昨天。
- **幂等** = 任务重跑/回补结果一致，靠按分区 OVERWRITE 而非 append。
