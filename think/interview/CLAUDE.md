## 三、讲解姿势（depth contract）

1. **先定位再讲。** 任何选题先挂到第二节的能力地图某一格，说明它在对标线的位置，再决定从哪起讲。
2. **系统重学一遍，但绝不停在「会用」。** 我承认基础生疏，可从概念稳稳铺起、宁可多讲；但每个专题**必须追到底层原理**，给「为什么这么设计 / 换个设计会怎样」。入门铺垫 + 资深挖深，两头都要。
3. **「平时在用」不是略过的理由。** 有手感的内容可以讲快点，但深度一分不少——面试官能追问的地方，笔记里都要有答案。
4. **默认我会编程**，把这当杠杆：能用 Go 写最小实现 / 起 Docker 复现 / 抓包 / 看 metrics 的，就别只讲文字。
5. **示例语言**：优先 **Go**；次选 Python；只有当组件本身是 JVM 系（Kafka/Spark/Flink 客户端、JVM 调优）才落到 Java，点到即止。
6. **往我熟悉的场景挂**：能用 Spark/Hive/Hadoop/ETL/数仓 举例的优先用——新知识挂旧钩子更牢。
7. **面试白板级收尾**：每个专题给一组**自测题**——「能口算 / 能白板推演 / 能扛三层追问」，达标才算吃透。
8. **真实出处**：引用官方文档、源码、RFC、论文；和已有笔记（`../infra/`、`../network/`）交叉链接，织成知识网。

## 四、学习方法：三角咬合 + 毕业标准

> 沿用 `../network/networking-infra-learning-roadmap-20260527.md` 的心法，适配后端中间件。

```
读原理（官方文档/源码/论文，搞懂「为什么」）
  └─→ 动手验证（Docker 起一个 / Go 写最小实现 / 压测 / 看 metrics / 抓包）
        └─→ 面试自测（白板讲清 + 口算 + 扛住追问，过了才算毕业）
```

- **只读会忘，只用不懂，三者咬合最快。**
- 每篇笔记结尾给「**毕业标准**」：不是「看过」，而是「能动手做出来 / 能在白板讲清楚」。

## 五、复习机制（三件事的第三件，别落下）

> 目录名立的是 **学习、沉淀、复习**。学习靠第三/四节，沉淀靠第八节，**复习靠这一节**。
> 准备面试时，复习是性价比最高的环节——不缺学习方法，缺的是「学完不忘、考前能快速捞回」。

1. **每篇笔记必须可抽考。** 第三节第 7 条要求给自测题——这些题要能**盖住答案自测**：题目集中放，答案折叠或置于题后，复习时先自己讲一遍再对照。
2. **30 秒电梯版。** 每篇开头给一段「盖住全文也能讲清主线」的极简回忆锚点（active recall），复习先过这段，卡壳就回挖。
3. **间隔重复节奏。** 笔记「毕业」后按 **+1 天 / +7 天 / +30 天** 各回看一次自测题；答不出就降级回「进行中」，重挖薄弱点。下次复习日期记在第六节总表里。
4. **复习也是审计。** 回看时若发现当初的理解经不起新追问，就地补进笔记——笔记是活的，不是写完封存。
