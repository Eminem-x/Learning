# LLM 训练流程:预训练、后训练与 RLHF

> 收录时间:2026-06-25 21:30 CST

## 一、整体流程

现代 LLM 从「一堆文本」到「能用的对话模型」,通常走三步:

```
┌─────────────────────────────────────────────────────────────┐
│  ① 预训练  Pre-training                                       │
│  海量互联网文本(万亿 token)→ 学「预测下一个词」              │
│  💰 最贵、最耗算力                                            │
│  产物:Base 模型(只会续写,不听话)                          │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  ② 后训练  Post-training(= 俗称的「微调」,但分多步)        │
│                                                              │
│   SFT 监督微调 ──► RLHF 偏好对齐 ──► 安全/工具/推理强化       │
│   教它「答」      教它「答得合人意」   教它「能用、安全」       │
│                                                              │
│  产物:Chat / Instruct 模型(会对话、听指令)                │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  ③ 产品化 → 上线给用户                                        │
│  gemini-2.5-flash / gemini-2.5-pro ...                        │
└─────────────────────────────────────────────────────────────┘
```

### 核心三步对照

| 步骤 | 输入 → 学什么 | 产物 | 类比 |
|------|--------------|------|------|
| ① 预训练 | 海量文本 → 预测下一个词 | **Base 模型**(只会续写) | 读完全图书馆,但不会聊天 |
| ② 后训练 | 指令对 + 人类偏好 → 对齐 | **Chat 模型**(会对话) | 学会怎么得体地回答 |
| ③ 产品化 | 蒸馏 / 量化 / 部署 | **上线模型** | 包装成产品卖 |

## 二、关于 flash / pro 命名

```
        ┌── gemini-2.5-pro    (大模型,各自独立训练)
2.5 代  ┤
        └── gemini-2.5-flash  (小模型,为速度 / 成本优化)
```

- **flash 不是在 pro 上「微调」出来的**,而是**两个独立的、不同尺寸的模型**,各自走完 ①②③。
- `flash` = 性价比 / 速度档位;`pro` = 性能档位;`2.5` = 代际版本。
- **例外**:小模型有时会用大模型做「**蒸馏(distillation)**」——让 flash 模仿 pro 的输出来提升质量,但这仍是独立训练,不是简单微调。

## 三、RLHF:用人类反馈做强化学习

全称 **R**einforcement **L**earning from **H**uman **F**eedback。目标:让模型不只是「答对」,而是答得**符合人类偏好**(有用、诚实、无害)。

### 为什么需要它?

SFT 只能模仿「标准答案」,但很多问题**没有唯一标准答案**(如「帮我安慰一下朋友」)。

> 关键洞察:**「评价好坏」比「写出范例」容易**。RLHF 就利用这一点。

### 三步流程

```
┌──────────────────────────────────────────────────────────┐
│  Step 1  收集人类偏好数据                                  │
│                                                            │
│  同一个问题,让模型生成多个回答:                          │
│       问题 ──► 回答 A / B / C                               │
│  人类标注员排序:  B > A > C                                │
│  攒几万~几十万条这种「谁更好」的对比数据                   │
└────────────────────────┬─────────────────────────────────┘
                         ▼
┌──────────────────────────────────────────────────────────┐
│  Step 2  训练「奖励模型」Reward Model (RM)                 │
│                                                            │
│  输入(问题 + 回答)──► 输出一个分数                        │
│  让它学会:人类喜欢的给高分,讨厌的给低分                  │
│  ✅ 本质:把「人类口味」压缩成一个可自动打分的模型          │
└────────────────────────┬─────────────────────────────────┘
                         ▼
┌──────────────────────────────────────────────────────────┐
│  Step 3  用强化学习优化主模型(常用 PPO)                  │
│                                                            │
│   主模型答题 ──► 奖励模型打分 ──► 分高强化,分低抑制        │
│        ▲                                  │                │
│        └──────────── 反复迭代 ◄───────────┘                │
│                                                            │
│  ⚠️ 加 KL 惩罚:别为讨好奖励模型跑得离原模型太远           │
└──────────────────────────────────────────────────────────┘
```

### 一句话理解三步

| 步骤 | 干什么 | 类比 |
|------|--------|------|
| 1 收集偏好 | 人给回答排序 | 美食评委尝菜打分 |
| 2 训奖励模型 | 把人的口味变成自动打分器 | 训练一个「电子评委」 |
| 3 强化学习 | 让模型不断改到高分 | 厨师反复改菜讨好评委 |

### 两个关键点

- **为什么要中间那个奖励模型?** 直接让人类对每次输出打分太慢太贵(训练要打分上百万次)。先把人类口味「蒸馏」进奖励模型,之后自动打分。
- **「钻空子」问题(reward hacking):** 模型可能发现奖励模型漏洞(如答案越长分越高 → 疯狂啰嗦),所以要加 **KL 惩罚**拴住它。

### 新趋势(简提)

- **RLAIF**:用 AI 反馈代替人类反馈,更便宜可扩展(Anthropic 的 **Constitutional AI** 即此思路)。
- **DPO**:跳过「奖励模型 + PPO」,直接用偏好数据优化主模型,更简单稳定。

## 附录:自我思考

- 一开始我把「微调」当成一个单步动作,其实**后训练是一组步骤**(SFT → RLHF → 安全/工具强化),「微调」只是俗称。
- 最容易误解的是 **flash/pro 的关系**:直觉上以为是「大模型微调出小模型」,实际是**不同尺寸的独立模型**,只是共享代际版本号和产品线。
- RLHF 最妙的一点是那个**认知杠杆**:「评价比创作容易」。这其实是个通用方法论——很多难以定义「标准答案」的任务,都可以转化为「让人/AI 做比较排序」来获得监督信号。
