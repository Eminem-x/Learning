# 词向量是怎么训练出来的:完整链路 + 数字走一遍

> 来源:个人思考(对话整理)
> 收录时间:2026-06-25 23:00 CST

---

本文用一个**最小玩具例子**,把「从一句话 → 调出词向量」的完整链路 ①→⑦ 走一遍,每一步都带具体数字。目标:建立一个**看得见、带数字**的心智模型。

> 前置只需:向量点乘、指数 $e^x$ 与对数 $\ln$、以及「导数 = 变化率」的直觉。**不需要会推导微积分也能跟下来**——求导结果直接给出。

---

## 一、完整链路全景

```
        ┌──────────────── 一次训练迭代 ────────────────┐
        │                                               │
 ① 文本   ② 查表      ③ 前向传播   ④ Softmax   ⑤ 损失     │
「猫→?」→ 取猫的向量 → 过输出层  → 出概率分布 → 比真实答案 │
        │                                               ▼
        │  ⑦ 更新参数       ⑥ 反向传播                   │
        └─ 挪坐标+调权重 ◄── 求每个参数的「责任」(梯度)◄┘
                │
                ▼
        重复几百万次 → 语义空间成形
```

整条链路只有一个真正的坎:⑥ 反向传播(求导)。其余 6 步都是高中~大一水平的乘加。

---

## 二、搭一个玩具模型

**词表**(4 个词,各给编号):

| 词 | 编号 |
|----|------|
| 猫 | 0 |
| 狗 | 1 |
| 喝 | 2 |
| 牛奶 | 3 |

**任务**:给一个词,预测下一个词。本轮训练样本是句子「**猫 喝**」→ 输入「猫」,正确答案「喝」。

**两组要学的参数**(初始值随便设的):

词向量表 E(每个词一个 2 维坐标):

| 词 | 向量 |
|----|------|
| 猫 | [0.3, 0.3] |
| 狗 | [-0.2, 0.5] |
| 喝 | [0.1, -0.4] |
| 牛奶 | [0.6, 0.2] |

输出层权重 W(每个词一行,用来给该词打分):

| 词 | 权重 |
|----|------|
| 猫 | [0.1, 0.2] |
| 狗 | [-0.3, 0.1] |
| 喝 | [0.4, -0.2] |
| 牛奶 | [0.2, 0.5] |

> 简化说明:真正的 Bengio 模型在中间还有一层 tanh 隐藏层,这里省掉了,**机制完全一样**,只是少几次乘加,方便手算。

## 三、逐步走一遍(带数字)

### ① + ② 文本 → 取出输入向量

输入是「猫」(编号 0),查表取出它的坐标:

$$x = [0.3,\ 0.3]$$

### ③ 前向传播:给每个候选词打分(logit)

每个词的得分 = 它的输出权重 $W_j$ 和输入向量 $x$ 的点乘:

$$\text{logit}_j = W_j \cdot x$$

| 词 | 计算 | logit |
|----|------|-------|
| 猫 | 0.1×0.3 + 0.2×0.3 | **0.09** |
| 狗 | -0.3×0.3 + 0.1×0.3 | **-0.06** |
| 喝 | 0.4×0.3 + (-0.2)×0.3 | **0.06** |
| 牛奶 | 0.2×0.3 + 0.5×0.3 | **0.21** |

> 此刻分数还很乱,「牛奶」分最高——因为参数是随机的,模型还没学。

### ④ Softmax:把分数变成概率

先取指数 $e^{\text{logit}}$,再除以总和(归一化),得到一个加起来 = 1 的概率分布:

| 词 | $e^{\text{logit}}$ | 概率 = $e/$总和 |
|----|------|------|
| 猫 | 1.0942 | 0.2526 |
| 狗 | 0.9418 | 0.2174 |
| 喝 | 1.0618 | **0.2451** |
| 牛奶 | 1.2337 | 0.2848 |
| 合计 | 4.3314 | 1.0000 |

> 模型现在认为下一个词是「喝」的概率只有 **24.5%**,而正确答案就是「喝」——猜偏了。

### ⑤ 损失:量化「猜得多偏」

用**交叉熵**:正确答案那一项的概率,取负对数。

$$\text{Loss} = -\ln P(\text{喝}) = -\ln(0.2451) = 1.406$$

> 直觉:正确答案的概率越低 → $-\ln$ 越大 → 损失越大。如果模型给「喝」打了 100%,损失就是 $-\ln(1)=0$。我们要把这个 1.406 往下压。

### ⑥ 反向传播:算出每个参数的「责任」(梯度)

这是核心。先看**输出分数**那一层,Softmax + 交叉熵有一个非常干净的结论:

$$\frac{\partial \text{Loss}}{\partial\, \text{logit}_j} = P_j - y_j$$

其中 $y_j$ 是真实答案(正确词为 1,其余为 0)。直接套:

| 词 | $P_j - y_j$ | 梯度 | 含义 |
|----|------|------|------|
| 猫 | 0.2526 − 0 | +0.2526 | 正 → 该**压低**它的分 |
| 狗 | 0.2174 − 0 | +0.2174 | 正 → 压低 |
| 喝 | 0.2451 − **1** | **−0.7549** | 负 → 该**抬高**它的分 ★ |
| 牛奶 | 0.2848 − 0 | +0.2848 | 正 → 压低 |

> 一眼看懂:正确词「喝」的梯度是负的 → 网络知道「我应该让喝的分更高」;其余词梯度为正 → 「这些我打分打高了,该降」。

接着把这个误差**继续往回传到输入向量** $x$(也就是「猫」的坐标)。结果是:用每个词的梯度,加权累加它们的输出权重:

$$\frac{\partial \text{Loss}}{\partial x} = \sum_j (P_j - y_j)\, W_j$$

代入算(逐维):

```
dim0 = 0.2526×0.1 + 0.2174×(-0.3) + (-0.7549)×0.4 + 0.2848×0.2 = -0.2850
dim1 = 0.2526×0.2 + 0.2174×0.1  + (-0.7549)×(-0.2) + 0.2848×0.5 =  0.3656
```

$$\frac{\partial \text{Loss}}{\partial x} = [-0.2850,\ 0.3656]$$

> 这个向量就是「猫的坐标该往哪个方向挪、才能减小损失」的**反方向**。

### ⑦ 更新参数:挪坐标 + 调权重

用**梯度下降**:参数 = 参数 − 学习率 × 梯度。取学习率 $\eta = 0.1$。

**更新「猫」的词向量**:

$$x_{\text{新}} = [0.3,\ 0.3] - 0.1 \times [-0.2850,\ 0.3656] = [\mathbf{0.3285},\ \mathbf{0.2634}]$$

**同时更新输出层「喝」那一行**(它的梯度 $= (P_\text{喝}-1)\cdot x = -0.7549\times[0.3,0.3]$):

$$W_{\text{喝,新}} = [0.4,\ -0.2] - 0.1\times[-0.2265,\ -0.2265] = [\mathbf{0.4227},\ \mathbf{-0.1774}]$$

> 「猫」的坐标动了一点点,「喝」的打分权重也朝着「下次给喝更高分」的方向挪了一点点。**一次迭代到此结束**,损失会比 1.406 略微下降。

## 四、为什么「猫」和「狗」会自己挤到一起?

上面只走了一步。现在想象语料里有大量句子,「猫」和「狗」**都经常接「喝」「可爱」**:

- 「猫 喝…」「狗 喝…」
- 「猫 可爱」「狗 可爱」

每次「猫→喝」,猫的坐标被推向「能让喝得高分」的区域;每次「狗→喝」,狗的坐标**被推向同一个区域**。

> 因为两者的**上下文几乎相同**,梯度反复把它们往**同一个方向**推 → 几百万步后,它们的坐标自然靠到了一起。

```
训练前:  猫 •            • 狗     (随机,离得远)
              ↓ 反复纠错 ↓
训练后:  猫 •• 狗                  (上下文相似 → 被挤到一起)
```

**没有人定义「猫和狗很像」**,是数据里它们用法相似,训练自己发现的。这就是语义空间「涌现」的全部秘密。

> 一句话:**"You shall know a word by the company it keeps."**(看一个词,要看它跟谁做伴。)

## 五、回头看,链路其实就这点东西

| 环节 | 一句话 | 用到的数学 |
|------|--------|-----------|
| ① 取词 | 查表拿坐标 | 无 |
| ③ 前向 | 点乘打分 | 向量点乘 |
| ④ Softmax | 分数 → 概率 | $e^x$、归一化 |
| ⑤ 损失 | $-\ln(\text{正确词概率})$ | 对数 |
| ⑥ 反传 | 梯度 = $P - y$,再往回传 | 求导(结果已给) |
| ⑦ 更新 | 参数 −= η×梯度 | 减法 |

> 真正的难点只有 ⑥,且它的核心结论 $P-y$ 异常简洁。其余全是乘加。**整条链路并不复杂,复杂感来自「串联」**——把 7 步首尾接成一个能往回流误差的环。走通两三遍就顺了。

## 附录:自我思考

- **最大的认知翻转**:词向量不是「设计」出来的,而是和网络权重一起,被「预测下一个词」这个目标**反向传播逼出来的副产品**。坐标的值本身没有人为含义,全由「谁和谁出现在相似上下文」决定。
- **难度被高估了**:动手前我以为要啃很多数学,实际真正的坎只有反向传播一处,而它的关键结论 $\frac{\partial L}{\partial \text{logit}} = P - y$ 简洁得惊人。其余环节都是高中~大一水平。
- **学习策略**:先用这种**带数字的玩具例子**把链路走通(半天~1天),再上 PyTorch 跑通看 embedding 真的在动(3~5天),最后才考虑徒手实现反向传播(1~2周)。**不必一上来啃 Bengio 原论文**。
- 与前两篇呼应:这套「预测下一个词 + 反向传播」的机制,正是 [[statistical-language-model-evolution-20260625]] 里统计方法的接棒者,也是 [[llm-training-process-20260625]] 中现代 LLM 预训练的最底层原理。从 N-gram 的「编号」到这里的「坐标」,是语言模型从「不会举一反三」到「会泛化」的关键一跃。
