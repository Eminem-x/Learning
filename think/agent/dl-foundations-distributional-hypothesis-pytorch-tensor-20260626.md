## 一、为什么语言模型需要「语义相似度」——分布假说

### 经典例子(出自 PyTorch 官方 Word Embeddings 教程)

训练数据里见过三句:

1. The mathematician ran to the store.(数学家跑去商店)
2. The physicist ran to the store.(物理学家跑去商店)
3. The mathematician solved the open problem.(数学家解决了那个未解难题)

来一句**从没见过**的新句子:

> The physicist solved the open problem.(物理学家解决了那个未解难题)

### 想利用的两个事实

| 事实 | 含义 |
|------|------|
| 事实一 | `mathematician` 和 `physicist` 出现在**相同的语境角色**里(都「跑去商店」)→ 二者有**语义关联** |
| 事实二 | 新句子里 `physicist` 出现的位置,正是过去 `mathematician` 出现过的那个角色(「solved the open problem」的主语) |

**连起来推理**:既然两词语义相近,而 `mathematician` 适合放进这个新句子,那么 `physicist` 放进去也应当合理。模型由此能「举一反三」。

### 关键点

- **相似 = 语义相似,不是拼写(orthographic)相似**。不是说 `mathematician` 和 `mathematics` 长得像,而是意思相关。
- **目的:对抗数据稀疏性(sparsity)**。语言组合无穷无尽,训练数据永远覆盖不全。相似度是一种「连点成线」的技术——用**见过的**推断**没见过的**。
- **背后的根本假设**:

> **出现在相似语境中的词,彼此语义相关。** 这就是**分布假说(distributional hypothesis)**。

一句更通俗的概括(语言学家 Firth 名言):**"You shall know a word by the company it keeps."**(观其伴,知其义。)这正是 word2vec、GloVe 乃至现代大模型嵌入层的理论根基:把词映射成向量,让语义相近的词在向量空间里靠得近。

## 二、PyTorch 是什么

**PyTorch** 是开源**深度学习框架**,最初由 Facebook(现 Meta)AI 团队开发,以 Python 为主要接口,是当前最主流的深度学习工具。一句话:**帮你搭建、训练、运行神经网络**。

### 三个核心能力

| 能力 | 说明 |
|------|------|
| **张量(Tensor)运算** | 类似 NumPy 的多维数组,但能放到 **GPU** 上高速并行计算 |
| **自动求导(Autograd)** | 训练靠反向传播,需要算大量导数;PyTorch 自动完成,不用手推公式 |
| **神经网络模块(nn)** | 提供搭积木式现成组件(全连接层、卷积层、嵌入层 `nn.Embedding` 等) |

### 极简示例

```python
import torch

x = torch.tensor([1.0, 2.0, 3.0])
w = torch.tensor([0.5], requires_grad=True)  # 需要求导的参数

y = (x * w).sum()   # 前向计算
y.backward()        # 自动求导
print(w.grad)       # 自动算出梯度,无需手动推导
```

### 名字含义与读音

- **读音**:/ˈpaɪtɔːrtʃ/ —— 「派-托奇」
- **Py** = Python(主要接口语言);**Torch** = 火炬,来自更早的 Lua 框架 **Torch**。PyTorch = 「Python 版的火炬」。

### PyTorch vs TensorFlow:现状

| 领域 | 主流选择 |
|------|---------|
| 学术研究 / 论文 | **PyTorch** 占绝大多数(约 80%+),新论文代码基本默认 PyTorch |
| 大模型(LLM) | 几乎全是 PyTorch 生态(Hugging Face、Meta LLaMA 等) |
| 工业部署 / 移动端 | TensorFlow 仍有一席之地(TF Lite、TF Serving),但差距在缩小 |
| Google 内部 | 自家的 **JAX** + TensorFlow |

**结论**:个人学习、研究、跟进大模型潮流 → **直接学 PyTorch**。TensorFlow 没消失,但从 1.x 到 2.x 的混乱让势头被反超。前沿研究里 **JAX**(同样 Google 出品)越来越火,但生态没 PyTorch 大,初学不用管。

> **TensorFlow** 读 /ˈtensɔːr floʊ/「滕瑟-弗洛」。Tensor = 张量,Flow = 流动,描述「张量数据在计算图中流动着被计算」的工作方式。
>
> 记忆窍门:**PyTorch** 强调语言(Python)+ 传承(Torch);**TensorFlow** 强调数据(Tensor)+ 机制(Flow / 计算图)。

## 三、张量(Tensor)和向量(Vector)的区别

关系是**包含**,不是并列:**向量是张量的一种特例**(vector ⊂ tensor)。按「阶 / rank / 几个轴」区分:

| 阶数 | 名称 | 直观理解 | 例子 |
|------|------|---------|------|
| 0 阶 | **标量 Scalar** | 一个数 | `5` |
| 1 阶 | **向量 Vector** | 一排数(一维) | `[1, 2, 3]` |
| 2 阶 | **矩阵 Matrix** | 一个表格(二维) | `[[1,2],[3,4]]` |
| 3 阶及以上 | **张量 Tensor** | 多维数组 | 一摞矩阵、立方体数据… |

深度学习语境里,**「Tensor」是统称**:标量 = 0 阶张量,向量 = 1 阶张量,矩阵 = 2 阶张量,再往上没有专名,统称张量。

```
标量:  5                  ← 一个点
向量:  [5, 3, 8]          ← 一条线
矩阵:  [[5,3,8],          ← 一个面(行×列)
        [1,2,9]]
张量:  [[[…],[…]],        ← 一个体 / 更高维
        [[…],[…]]]
```

**为什么深度学习老说 tensor**:真实数据往往高维,向量不够用。例如一批彩色图片:

```
形状:  [32, 3, 224, 224]
       ↑    ↑   ↑    ↑
      32张  RGB 高   宽
      图片  3通道
```

这是 **4 阶张量**,没法用向量或矩阵描述。所以 PyTorch / TensorFlow 都用 **Tensor** 作最基本数据单位——它能涵盖任意维度。

> **一句话**:向量是「一维的张量」,张量是向量向任意维度的推广。所有向量都是张量,但不是所有张量都是向量。
>
> ⚠️ 注意:物理 / 数学里严格定义的 tensor 还要求「在坐标变换下如何变化」的性质,更严格;深度学习里说的 tensor 基本就是「多维数组」这个朴素意思。

## 附录:自我思考

- **三个概念是一条逻辑链**:分布假说回答「为什么要用向量表示词」→ 张量回答「向量在工程上的一般形式是什么」→ PyTorch 回答「用什么工具把它跑起来」。从「为什么」到「是什么」到「怎么做」。
- **容易混的两组词**:① 语义相似 ≠ 拼写相似(分布假说关心前者);② 向量 ≠ 张量并列,而是被包含。两处都是「以为是一回事,其实是子集 / 不同层面」的误区,澄清后概念地图清晰很多。
- **工具选型不必纠结**:PyTorch 已是事实标准,跟着它走能直接对接 Hugging Face 和绝大多数论文代码;TensorFlow / JAX 等遇到再补。
