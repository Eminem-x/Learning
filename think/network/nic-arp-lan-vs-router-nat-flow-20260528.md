# 包到底怎么送出去：网卡、ARP、内网直连 vs 走路由器 NAT

> 来源：个人学习（网络地基 · 阶段一收尾）
> 收录时间：2026-05-28 16:35 CST
>
> 本文用本机（一台连着 `10.0.14.0/23` 网络的 Mac）的真实 `ifconfig` / `netstat -rn` / `arp -a` 数据，
> 把「一个包从应用出生到真正离开机器」的全过程拆开，重点解决两个卡点：
> **ARP 是什么** 和 **「内网直接走链路层、不经过 IP 层」这句话哪里对、哪里错**。

---

## 0. 先把两个误解正面掐死

> 我的原话困惑：「内网访问直接走链路层？不经过 IP 层？」

这句话**一半对、一半错**，必须分清，否则后面全乱：

| 说法 | 对错 | 说明 |
|------|------|------|
| 内网访问「不经过 IP 层」 | ❌ **错** | 包**永远有 IP 头**，源 IP / 目的 IP 一直在。你和对方两端都走 IP 层。 |
| 内网访问「不经过路由器的三层转发」 | ✅ **对** | 中间的交换机 / WiFi AP 只看 **MAC（二层）** 转发，**不拆 IP**。路由器（网关）根本不参与。 |

一句话纠正：
> **内网直连，省掉的是「路由器转发」，不是「IP 层」。** 包照样有 IP 头，只是没有任何设备对它做三层路由——中途的交换机只按 MAC 把帧递过去。

为什么会有这个误解？因为「走链路层」这个说法把**两件事**混在一起了：
- **你的电脑**造包、收包：三层（IP）+ 二层（MAC）都要做。
- **中间的交换机/AP**：只做二层（按 MAC 转发），不碰 IP。

所以「直连」≠「没有 IP」，而是「中间没人做 IP 路由」。

## 1. 网卡（NIC）：通向某个网络的一扇门

**网卡 = 你这台机器通向「某一个网络」的一扇门。** 物理网卡背后要么是天线（WiFi），要么是网口（网线）。

本机真实存在的网卡（`ifconfig` 节选）：

| 接口 | 是什么 | 状态 | IP |
|------|--------|------|-----|
| `en0` | WiFi 网卡（天线） | **active** | `10.0.14.220/23` |
| `en1/en2/en3` | 雷雳口（网线） | inactive | 无（没插线） |
| `lo0` | 回环（虚拟） | up | `127.0.0.1` |
| `utun0~3` | 系统隧道（虚拟） | up | 无 IPv4 |

没插线 / 没连接的网卡 = `inactive`：门在那，但没通向任何地方。

每块网卡有**两个身份**，这是理解一切的根：

| 身份 | 例（本机 en0） | 谁给的 | 作用 | 层 |
|------|------|--------|------|----|
| **MAC 地址** | `bc:d0:74:42:5e:b1` | 出厂烧死在硬件 | **同一局域网内**找到那块网卡 | L2 链路层 |
| **IP 地址** | `10.0.14.220` | 软件配的（DHCP/手动） | **跨网络**找到对方 | L3 网络层 |

> 🥚 `ifconfig` 里 en0 的 MAC 可能显示成另一个值（如 `52:06:...`），那是 macOS 连陌生 WiFi 时的 **MAC 随机化**（防追踪），真实硬件 MAC 用 `networksetup -listallhardwareports` 看。这恰好证明「MAC 是硬件身份」。

**关键：一台机器可以有多块网卡，每块接入不同网络。** 路由器 / OPNsense 本质就是**有两块以上网卡的机器**：

```
        ┌─────────────── 路由器 ───────────────┐
内网 ───│ 网卡A(LAN)              网卡B(WAN) │─── 外网
        │ 10.0.14.1               1.2.3.4(公网)│
        └──────────────────────────────────────┘
```

包「网卡A 进、网卡B 出」的那一刻被改写 —— 那就是 NAT。

## 2. 虚拟网卡：没有硬件的「假门」

虚拟网卡行为跟真网卡一样（能配 IP、收发包、进路由表），但背后没有线。**包发进去后不上线缆，而是交给某个程序处理。**

| 接口 | 包发进去后去哪 |
|------|--------------|
| `lo0` | `127.0.0.1`，**永不出机器**，自己发给自己 |
| `utun0~3` | 交给 macOS 系统服务 |
| `utun4`（VPN 开启时才有） | 交给 **OpenVPN 程序** → 加密 → 套外层信封 → 再从真网卡 `en0` 发出 |

虚拟网卡 = **程序伸进网络栈的一只手**：系统以为是张正常网卡照常把包丢进去，其实被程序截走了。这就是「信封套信封」在物理上发生的地方。

## 3. ARP：把 IP 翻译成 MAC（最缺的那一环）

### 问题
要把帧真正放上线缆（二层），必须填 **目的 MAC**。可路由决策给你的是 **下一跳的 IP**。
> 我知道你的 IP，但帧得写 MAC —— 这中间的翻译，就是 ARP 干的。

### ARP 是什么
**ARP（Address Resolution Protocol，地址解析协议）= 在同一个局域网内，把「IP 地址」翻译成「MAC 地址」。**

### 怎么工作（广播问、单播答）
假设你要找 `10.0.14.175` 的 MAC：

1. **广播喊话**：你的 Mac 朝全网段所有人（目的 MAC = `ff:ff:ff:ff:ff:ff`）喊：
   > 「谁是 `10.0.14.175`？请把你的 MAC 告诉 `10.0.14.220`。」
2. **本人单播回答**：只有 `10.0.14.175` 那台机器回：
   > 「是我，我的 MAC 是 `ca:41:cd:f6:b2:aa`。」
3. **缓存下来**：你的 Mac 把这条记下，存进 **ARP 表**，下次不用再问。

`arp -a` 看到的就是这张缓存表。本机真实片段：

```
? (10.0.14.1)   at bc:24:11:a3:99:22   on en0   ← 网关的 MAC
? (10.0.14.175) at ca:41:cd:f6:b2:aa   on en0   ← 某个同事设备
? (10.0.14.183) at (incomplete)        on en0   ← 问了没人答（设备离线/不存在）
```

> `(incomplete)` = ARP 问出去了但没回应，说明那个 IP 当前没人占用或设备掉线。

**ARP 只在同一个局域网内有效**——它靠广播，而广播出不了路由器。跨网段时你永远不会去 ARP 远方的目标，只会 ARP「下一跳网关」。

## 4. 统一模型：路由决定「下一跳 IP」，ARP 把它变成「MAC」

这是把第 0 节那个误解彻底解开的核心。**任何一个包要出门，都走这两步**：

```
第一步（三层 / 路由表）：目的 IP 落在哪条路由？→ 算出「下一跳 IP」
第二步（二层 / ARP）  ：把「下一跳 IP」翻译成 MAC → 填进帧的目的 MAC
```

差别只在「下一跳 IP 是谁」，分两种情况：

### 情况 A：目标在同网段（访问同事 `10.0.14.175`）

```
路由表：10.0.14.175 ∈ 10.0.14.0/23（本地直连）→ 下一跳 = 10.0.14.175 它自己
ARP  ：谁是 10.0.14.175？→ ca:41:cd:f6:b2:aa
封帧 ：
   [ 以太网 | dstMAC = ca:41:cd:f6:b2:aa  ]  ← 直接写对方的 MAC
   [ IP     | dst    = 10.0.14.175        ]  ← 终点也是它
```
帧路径：`你的 Mac → WiFi AP（交换机，只看 MAC 转发）→ 同事`。
**路由器 `10.0.14.1` 全程没参与。** —— 这就是「内网直连」。但注意：**IP 头一直在**，两端都走 IP 层，只是中间没人做三层路由。

### 情况 B：目标在网段外（访问公网 `8.8.8.8`）

```
路由表：8.8.8.8 不在 10.0.14.0/23 → 落到 default → 下一跳 = 网关 10.0.14.1
ARP  ：谁是 10.0.14.1？→ bc:24:11:a3:99:22
封帧 ：
   [ 以太网 | dstMAC = bc:24:11:a3:99:22  ]  ← 写「网关」的 MAC（不是 8.8.8.8 的！）
   [ IP     | dst    = 8.8.8.8            ]  ← 终点是 8.8.8.8
```

🔑 **全网最容易绕晕的点，盯死：**
> **dst MAC = 下一跳（网关）；dst IP = 最终终点（8.8.8.8）。**
> 你够不着 8.8.8.8，但够得着网关。所以二层写「先递给网关」，三层写「我最终去 8.8.8.8」。
> **IP 是终点，MAC 是下一跳。** 每过一跳，MAC 都换；IP 一路不变（除非被 NAT 改）。

## 5. NAT 出门完整流程（情况 B 的后半段）

角色（真实数据 + 公网 IP 用假设值 `1.2.3.4`）：

| 角色 | 地址 | MAC |
|------|------|-----|
| 你的 Mac（en0） | `10.0.14.220` | `bc:d0:74:42:5e:b1` |
| 网关 / 路由器 LAN 口 | `10.0.14.1` | `bc:24:11:a3:99:22` |
| 路由器 WAN 口 | `1.2.3.4`（公网，假设） | — |
| 目标 | `8.8.8.8` | — |

### 🟢 出门（请求）

**① 造包**（应用挑源端口 `54321`）：
```
[ IP  | src=10.0.14.220  dst=8.8.8.8 ]
[ TCP | sport=54321       dport=443  ]
```

**② 路由决策**：`8.8.8.8` → default → 下一跳 `10.0.14.1`，出 `en0`。

**③ ARP**：`10.0.14.1` → `bc:24:11:a3:99:22`，封帧（dstMAC = 网关，dstIP = 8.8.8.8）。

**④ 上天线** → WiFi AP → 到达**路由器 LAN 网卡**。

**⑤ NAT 发生（SNAT，改源）**：路由器要往 WAN 口转发，先改源地址：
```
改前：[ src=10.0.14.220:54321  dst=8.8.8.8:443 ]
改后：[ src=1.2.3.4:60001      dst=8.8.8.8:443 ]
```
并在 **NAT 表（账本）**记一笔：
```
1.2.3.4:60001  ←→  10.0.14.220:54321   (目标 8.8.8.8:443)
```

**⑥ 为什么必须改**：`10.0.14.220` 是**私网地址**，全世界无数网络都在用 `10.x`，公网没有任何路由能找回你。不改的话回信寄给 `10.0.14.220` 永远送不到。路由器把源换成自己**全球唯一的公网地址**，意思是「回信寄给我，我记得这是 220 的」。

**⑦ 从 WAN 口发出** → 运营商逐跳转发（每跳换 MAC，IP dst 始终 `8.8.8.8`）→ 到达 `8.8.8.8`。

### 🔵 回门（响应）

**⑧ `8.8.8.8` 回包**（它眼里你**从来就是 `1.2.3.4`**，根本不知道 `10.0.14.220` 存在）：
```
[ IP  | src=8.8.8.8  dst=1.2.3.4  ]
[ TCP | sport=443     dport=60001 ]
```

**⑨ 回到 WAN 口，反查 NAT 表（DNAT，改目的）**：`1.2.3.4:60001` → 账本写着是 `10.0.14.220:54321`，改回去：
```
改前：[ src=8.8.8.8:443  dst=1.2.3.4:60001     ]
改后：[ src=8.8.8.8:443  dst=10.0.14.220:54321 ]
```

**⑩ 从 LAN 口送回 Mac**（ARP 找你的 MAC，封帧，发出）。你的 Mac **以为是 `8.8.8.8` 直接回的**，完全不知中间被 NAT 改了两次。

### 一图收尾
```
出门: Mac ──src=10.0.14.220──> [路由器:改源] ──src=1.2.3.4──> 8.8.8.8
回门: Mac <──dst=10.0.14.220── [路由器:改回] <──dst=1.2.3.4── 8.8.8.8
                                   ↑ 靠 NAT 表配对
```

## 6. 心法总表（背下来）

| # | 心法 |
|---|------|
| 1 | **IP = 终点，MAC = 下一跳。** IP 一路不变（除非 NAT），MAC 每跳都换。 |
| 2 | 出门两步：**路由表算「下一跳 IP」→ ARP 把它翻译成 MAC**。 |
| 3 | 同网段：下一跳 = 目标自己，直连，路由器不参与（但 IP 层照走）。 |
| 4 | 跨网段：下一跳 = 网关，dst MAC 写网关、dst IP 写终点。 |
| 5 | 路由器 = 多网卡的机器，**NAT 发生在两块网卡的交界处**。 |
| 6 | 出门改源（SNAT）、回门改目的（DNAT），靠 NAT 表配对两个方向。 |
| 7 | 私网地址（10.x / 192.168.x / 172.16~31.x）出不了门，必须借路由器公网地址当回信地址。 |
| 8 | ARP 靠广播，只在本网段有效，出不了路由器。 |

## 附录：自我思考

- **「内网直连不经过 IP 层」这个误解的根**：把「我这台机器的协议栈」和「中间转发设备的职责」混为一谈了。交换机不碰 IP ≠ 包没有 IP。今后凡遇到「不经过某层」的说法，先问一句：**说的是哪台设备的视角？** 端机和中间设备做的事完全不同。
- **ARP 是「路由」和「真正发包」之间缺的那块拼图**。之前只学了路由表算下一跳，但「下一跳 IP 怎么变成线上的帧」一直悬空——ARP 就是这一步。把「路由决定下一跳 IP → ARP 解析成 MAC → 封帧上线」这条链背熟，整个出门流程就闭合了。
- **NAT 的本质不神秘**：私网地址在公网无法回址，所以借公网地址、记账、回来时按账本改回。所有复杂（端口映射、回流/hairpin、CGNAT）都是这条主线的变体。
- **下一步**：把 VPN 那条隧道叠回这套流程——它不过是在「出门」这步之前，先让 `utun` 虚拟网卡把包交给程序加密、再当作一个普通的「访问公网 IP」走一遍本文的流程。本质是同一套机制多套一层。
