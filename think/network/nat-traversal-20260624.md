# 内网穿透：让内网服务被公网访问

> 来源：个人思考
> 收录时间：2026-06-24 17:35 CST

---

## 一、要解决的问题

家庭宽带通常分配的是**运营商内网 IP**（藏在运营商 NAT 后面），没有可直达的公网 IP。结果是：

- 内网设备能**主动出去**上网；
- 但外部**进不来**——公网上没有一个地址能直接找到它。

```
你在外面 ──❌──→ 家里的 NAS / 服务
                 （内网 IP，藏在 NAT 后面，外面找不到它）
```

**内网穿透**就是专门解决「让没有公网 IP 的内网服务，变得可以从公网访问」的一类技术。

---

## 二、核心原理：由内向外「打洞」

既然外面进不来，就反过来——**让内网设备主动连接一台有公网 IP 的中转点，建立一条隧道，再借这条隧道把外部流量引回内网。**

```
外部用户 → 公网中转点（VPS / 服务商） ←──隧道──← 家里内网设备（主动连出去）
```

关键点：

1. 隧道由**内网设备主动发起**（出方向 NAT 是放行的）；
2. 隧道建好后双向可通；
3. 外部请求顺着隧道流回内网，从而绕过「进不来」的限制。

---

## 三、深入：隧道（Tunnel）到底是什么

上面反复出现的「隧道」，是内网穿透乃至 VPN 的**底层机制**。它的核心只有一个动作：**封装（encapsulation）——把一个数据包，塞进另一个数据包里运输。**

> **隧道 = 把「原始数据包」当成货物，装进「外层数据包」这个集装箱里，经过一段网络运输，到对端再拆开还原。**

### 信封比喻

原始数据包的目标是一个**公网不认识的内网地址**，直接发会被退回。隧道的做法是把整个原始包（连同它的内网地址）**塞进一个新信封**，新信封写的是公网认识的地址：

```
外层信封（公网能送达）：
  ┌──────────────────────────────────────┐
  │ 收件人：1.2.3.4（对端隧道口的公网 IP）  │  ← 公网照常投递
  │ 内容（货物）：                         │
  │   ┌─────────────────────────┐         │
  │   │ 收件人：192.168.1.5      │ ← 原始包原封不动塞在里面
  │   │ 内容：你好               │         │
  │   └─────────────────────────┘         │
  └──────────────────────────────────────┘
```

公网只看**外层信封**，送到对端隧道口；对端**拆开外层、取出原始包**，在自己内网正常投递。原始包全程无感知自己穿过了公网——像火车穿过山体隧道，山（公网）看不到也管不着隧道里跑的是什么。「隧道」之名由此而来。

### 两个动作就是全部

| 动作 | 在哪做 | 干什么 |
|---|---|---|
| **封装（encapsulation）** | 隧道入口 | 给原始包套一层外层包头（新地址） |
| **解封装（decapsulation）** | 隧道出口 | 剥掉外层，还原原始包，继续投递 |

中间经过的所有路由器，只处理外层包头，对内层一无所知。

### 隧道能带来三种能力

| 能力 | 说明 | 例子 |
|---|---|---|
| **① 连通** | 让两个本来够不着的网络像连在一起 | frp 内网穿透、组虚拟局域网 |
| **② 加密** | 内层包藏在外层里，可顺便加密保护 | VPN / WireGuard |
| **③ 协议穿越** | 用一种网络运另一种 | IPv6 包套在 IPv4 里传输 |

### 关键澄清：隧道 ≠ VPN ≠ 加密

- **隧道**是通用机制（封装），**本身不一定加密**（如 GRE、纯 IP-in-IP 就是明文）。
- **VPN** = 隧道 + 加密 + 让你「像在那个网络里」，是隧道的一种特定用法。
- **WireGuard** = 一个具体的加密隧道协议（所以能用来做 VPN）。
- **frp 内网穿透** = 用隧道实现「连通」，重点在打通而非加密。

```
                    隧道（封装，通用机制）
                   /         |          \
            frp 穿透     WireGuard      IPv6-over-IPv4
           (重连通)   (隧道+加密=可做 VPN)  (重协议穿越)
```

它们底层是同一个动作：**封装 + 解封装**，只是外层用什么协议、加不加密、为连通还是为安全，侧重点不同。

## 四、四类常见方案

| 方案 | 原理 | 前提条件 | 适合场景 |
|---|---|---|---|
| **① 端口转发 / 映射** | 路由器把公网端口直接映射到内网设备 | **必须有公网 IP** | 家里确实有公网 IP 时最直接 |
| **② frp / nps（自建）** | 自己在 VPS 上跑中转，内网跑客户端 | **一台有公网 IP 的 VPS** | 想完全掌控、学习价值高 |
| **③ Cloudflare Tunnel / ngrok / 花生壳** | 用第三方现成的中转服务 | 一个账号（免费 / 付费） | 图省事，不想买 VPS |
| **④ Tailscale / ZeroTier（组网类）** | 基于 WireGuard 组虚拟局域网，P2P 直连 | 装客户端 + 注册账号 | 自己多设备互访，最省心 |

---

## 五、两个最实用的方案详解

### 方案②：frp + VPS（经典自建）

把 VPS、公网 IP、隧道、反向代理等知识全部串起来的方案：

```
家里：内网服务  →  frpc（客户端，主动连 VPS）
                        ↓ 隧道
公网：租用的 VPS（公网 IP）  →  frps（服务端，接收外部访问）

外部用户 → 访问 VPS 的 IP:端口 → 经隧道 → 到达家里服务
```

- **优点**：完全自己掌控、无第三方审查、学习价值最高（VPS + 隧道 + 反向代理一次打通）。
- **成本**：一台 VPS（约 $5/月）。

### 方案④：Tailscale / ZeroTier（自己访问自己，最省心）

当需求是「我自己在外面访问家里设备」（而非对公众提供服务）时最合适：

- 在所有设备（家里的、手机、笔记本）装客户端，登录同一账号；
- 它们自动组成一个**虚拟局域网**，互相直连，如同处在同一房间；
- 不用买 VPS、不用配端口，基本零配置；
- 底层是 WireGuard，尽量 P2P 直连，连不通时自动找中转。

---

## 六、怎么选

| 需求 | 推荐方案 |
|---|---|
| **就我自己**在外面访问家里设备 | **Tailscale**（方案④）——最省心 |
| 想**对公众提供服务**（网站 / API） | **frp + VPS**（方案②）——学习价值最高 |
| 完全不想折腾、临时 demo | ngrok / Cloudflare Tunnel（方案③） |
| 家里**真有公网 IP** | 端口转发（方案①）——最直接 |

---

## 七、安全提醒

内网穿透 = 给家庭网络开了一个公网口子。任何把内网暴露到公网的操作，都必须配套：

- 强密码、**密钥登录**（禁用密码登录）；
- **最小化开放端口**，只开必要的；
- 明确的**防火墙规则**（OPNsense 正好可在此兜底）。

否则等于给家里开了一扇没锁的门。

## 附录：自我思考

- **概念串联**：内网穿透是「家宽无公网 IP」这一痛点的直接解药，而它又复用了前面学到的 VPS、公网 IP、NAT、防火墙等概念——可以作为检验这些基础是否真正掌握的一个综合落点。
- **选型的本质分歧**：方案的核心分水岭是「给自己用」还是「给公众用」。前者走组网（Tailscale），后者走中转（frp + VPS）。先想清楚目的，再选方案，能避免过度工程。
- **与变现目标的关系**：若目标是「做对外服务变现」，frp + VPS 这条路顺带打通了公网部署能力，比 Tailscale 更贴近最终诉求；Tailscale 更适合作为低风险的第一次动手练习。
- **隧道是统一底座**：内网穿透、VPN（WireGuard）、跨云组网，表面是不同工具，底层都是同一个「封装 + 解封装」。抓住这一点，`network/` 里的多篇笔记其实是一棵树的不同枝叶，不必各自孤立记忆。
- **下一步待验证**：实操一次 Tailscale（约 10 分钟、零成本零风险），用最小代价把「内网穿透」从概念变成「真做过一次」；并可对一次 WireGuard 连接抓包，亲眼验证「外层 UDP 包 + 内层加密原始包」的封装结构。
